# Browser streaming design

Enable the installed PixelStreaming2 plugin and rebuild the existing Linux package. Match the official infrastructure/frontend to UE5.8 and pin downloaded dependencies. A lifecycle script starts Epic's signalling server and two separately identified game processes: NordHost listens for normal Unreal multiplayer, NordFriend1 joins it. Only NordHost owns campaign saves. Avoid competing Unreal GPU jobs and terminate only processes this script owns.

The small browser player reuses NORD's existing ink/yellow HUD palette and official input/media implementation. Vercel hosts static HTML/CSS/JS; the configured WSS endpoint connects directly to the PC's signalling service. Keep endpoints in deployment configuration, disallow production ws://, and disable arbitrary query overrides. Browser play must require real stream readiness and a click gesture for sound/input; offline or occupied streams must remain explicit.

Inspect existing Tailscale Serve/Funnel configuration before temporarily exposing signalling. Preserve unrelated services. Use STUN for the initial direct WebRTC trial; a TCP signalling tunnel does not relay media. If the external ICE route fails, record the need for a public TURN relay instead of claiming public play works. Never publish local credentials or Unreal streamer ports.

Build and test the frontend locally before deploying a separate public Vercel project. Verify the intended team/project/environment. Vercel deployment success alone does not verify game streaming. Keep the change active until actual external-browser access is demonstrated or its missing network prerequisite is recorded.

The final hosting method runs the same lifecycle/Funnel commands in two named transient user services, `nord-browser-demo` and `nord-browser-funnel`, avoiding tool-terminal cleanup. No static service files, enable, automatic restart or reboot persistence are added. Stop only those owned units; preserve unrelated user services and Tailscale Serve configuration. Manual foreground start/stop remains an alternative.

A later restart with a competing GPU application hit Vulkan OOM in the friend. Both owned units were stopped cleanly at that point and subsequently restored after sufficient headroom was available. Preflight now requires at least 12,000 MiB free on NVIDIA adapter 0 through nvidia-smi and refuses known insufficient headroom before launching children. This calibrated threshold does not reserve VRAM or guarantee stability against later allocations. The recovered launch and later ordinary-browser checks are recorded in the verification documents.

Final bounded calibration uses 1280×720 output, a High (2) base with global illumination/reflection/shadow quality 1, virtual shadow maps disabled and 75% internal screen percentage. Render/WebRTC is capped at 30 FPS with VP8 software encoding, synchronous MediaIO capture and an 8 Mbps start / 12 Mbps video ceiling per slot. The final 30-second dual-stream sample averages 23.1/24.2 decoded FPS; it does not establish sustained/remote driving responsiveness. H264 connected but delivered no frames and stalled capture on this Linux host; retain the supported VP8 path until engine/driver updates can be retested. Development debug key bindings and Pixel Streaming ConsoleCommand payloads are disabled. The current command uses corrected PixelStreamingKeyFilter=Tilde, verified as a parsed native setting by an isolated package NullRHI check; full rendered filtering remains deferred. Earlier live runs used the unknown PixelStreamingInputKeyFilter argument and did not establish effective Tilde filtering. Upstream resolution control still permits resource-load changes by a subscribed input owner. Browser disconnect releases native held keys and its owned worklight through the existing authoritative controller, while retaining possession and progress.

The host PC resolves its own Funnel hostname to a tailnet address. Chromium can block that cross-origin local-network connection; the isolated QA browser resolves that one hostname to its published public Funnel IP for deployment checks. No global DNS or browser security setting is changed. This still tests on the host network and cannot substitute for an off-LAN media test.
