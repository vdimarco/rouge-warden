# Design

Use existing player DOM states to gate ready/playing media callbacks. A control-channel error releases touch keys before closing its SDK connection; native BrowserDisconnected already releases pawn input when the owned connection closes. Preserve the specific error through subsequent disconnect notification. Occupied-slot refusal still retains its signalling socket for selecting another player. A real-stream trace found an older Host refusal arriving after a Friend selection, leaving a connected peer behind an error. Keep the selector disabled during pending subscription and re-enable on readiness/refusal so requests cannot overlap; preserve live selector updates while already playing. The SDK reconnect first closes its old socket; mark that in-progress handoff so its disconnect cannot poison the replacement, then clear it on readiness/failure/cancel. Ignore subscription refusals outside a pending subscription. No new state-machine layer or library. Change held move-stick opacity from zero to 0.7, retaining its knob position and footprint.

Reach: player.js media/failure callbacks, styles.css movement feedback, existing actual-SDK browser UI and live-input checks, README, evidence and capability specs. Reproduce with late DOM/SDK events against a real browser, test actual session closure/reconnection on the native stream and inspect held-stick feedback. No native authoring/build/restart, rendering technique or game asset change. Physical phones/carrier failures remain unverified. OpenSpec CLI unavailable; validate artifacts/scenarios manually.
