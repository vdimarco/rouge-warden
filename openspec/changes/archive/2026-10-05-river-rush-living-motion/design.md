## Implementation direction
Use the existing runner layout and art direction; this is a motion pass, not a screen redesign. Generate actual paddling frames from the approved character atlas. New Higgsfield river clips were attempted, but the provider rejected both before submission because the workspace has no credits. The user then requested fal.ai; use its matched-frame river loops as the primary water animation, with GPU texture flow/displacement and still/foam fallbacks. No generation calls occur at runtime.

The renderer consumes simulation-time motion state in a WeakMap keyed by each run. An offscreen WebGL scene blends two phase-shifted water texture samples for continuous advection and small ripples, masked conservatively to the river surface. Cache the latest frame and update only when simulation time or viewport changes, so paused/completed frames stay identical. Reduced motion uses still art. Context absence/loss uses the original image plus moving foam, without affecting controls or collision rules.

Character loop frames are anchored to the raft base. Blend ride/jump/duck over approximately .08 s, bank into lane swaps, show jump lift and a short landing squash/rebound. Landing events carry only visual/audio feedback and never alter collision/score rules. Source coin metadata enables sprite flights to the actual counter; magnet pickups arc from other lanes; Rush destroys obstacles in short bounded bursts. Effects use simulation time and existing per-run bounds.

Use a small pure motion module for frame index/pose weights/pulses so deterministic, paused, reduced-motion and reset behavior can be tested without a browser. Browser tests directly compare captured video/canvas frames, pause equality, real keyboard/touch actions, GPU fallback and live motion preferences. Check desktop 1536×1024, phone 390×844, landscape 844×390 and DPR2. Measure warmed active-play frame timings; report browser measurements without physical-phone claims.
