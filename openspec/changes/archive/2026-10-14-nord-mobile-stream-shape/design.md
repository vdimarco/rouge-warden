# Design

Current phone profiles use a long edge plus a 16:9 landscape frame. At 390×844 the 960 profile requests about 444×960 (426k pixels), below 960×540 (518k). Fullscreen wide landscape uses CSS fill, stretching 16:9 horizontally. Use area = edge²×9/16 and the actual play-area aspect ratio to derive even native dimensions, rounded down to retain the existing pixel ceiling. Use CSS contain so orientation changes do not distort an old frame while the new frame arrives. Keep all profile bitrate ceilings and adaptation thresholds unchanged unless measurements demonstrate a separate fault. Keep NORD_PORTRAIT_STREAM=0 at its legacy 16:9 fallback.

Adapted reference: [MDN object-fit](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/object-fit): contain preserves aspect ratio and the entire frame; fill distorts when ratios differ. [MDN inbound RTP stats](https://developer.mozilla.org/en-US/docs/Web/API/RTCInboundRtpStreamStats) informs decoded FPS/buffer reporting. No new dependency or native renderer change.

Validation: deterministic dimension/budget cases; real native frames and screenshot review in portrait, landscape, rotation and fullscreen; existing mobile input/adaptation/recovery checks. Extend the existing sampler with --portrait for before/after one-minute same-machine measurements. Browser plugin not available; use existing Playwright fixtures. Record the source, fresh package/save baseline and deployment identities. Phone/carrier and image-quality metrics remain unverified.

A real WSS regression run exposed a disconnected original viewer with a connected peer after its replacement reconnect. The pinned Epic SDK's tryReconnect sets forceReconnect even when doReconnect finds the socket already CLOSED and connects immediately; that flag is consumed on the *next* disconnect, scheduling an unintended retry. Use the existing protocol.isConnected() before choosing SDK reconnect, and use ordinary connect for CLOSED sockets. The SDK treats CLOSING as connected, so its existing close/handoff path remains intact. This prevents a later explicit Disconnect from reopening a hidden stream/occupying the slot. Strengthen the real peer test to wait through the three-second close/retry window and assert no connected peer remains before another viewer acquires it. Reference: installed lib-pixelstreamingfrontend-ue5.8@0.1.2 WebRtcPlayerController.ts tryReconnect/doReconnect/onClose; common WebSocketTransport.ts isConnected.
