# Design

Moonlit citadel, midnight teal, ivory and antique gold; retain native readable controls, transparent hero portraits and painted spell icons. Inspect a complete UI concept before integrating a generated background. Preserve the viewport-contained footer and roster flow.

Inspected the completed full-screen concept and independent environment before integration. Adopt its moonlit lake, ruined citadel, empty hero terrace and quiet dark UI areas. Keep the existing Nessie sprite and 3x4 roster layout; preserve the current viewport grid, labels, role filters and spell previews. The concept’s regenerated creature portraits and altered role labels are intentionally replaced by the playable native assets and actual roster categories. The concept is a direction reference, not a background containing controls.

Use a local 2752x1536 WebP environment (162,328 bytes), an independent CSS layer over an opaque dark fallback, and image preload. If the file fails, native controls remain on the dark background and Start is not blocked by the decorative art. The narrow-screen background favors the moon/citadel side. No extra decorative animation is added. Skip battlefield drawing while selection is open because the cinematic stage fully covers it.

Verification: the deployed preview at 1363x936 displays the local Fal environment, unchanged native 3x4 roster and a reserved footer. DOM bounds show no page overflow and a 22px gap between roster bottom and footer. Assassin filtering, Mothman selection, Night flight preview, Start, direct HUD plus training, active battlefield rendering, pause and return were exercised with real controls. No app-origin warnings or errors were observed. The inspected concept informed environment composition and palette; final typography, role categories, portraits and viewport layout remain native and deliberately differ from its generated UI. A stronger top scrim and text shadow improve subtitle contrast against the moon.

Background-failure behavior was inspected in code: CSS artwork is independent of loadArt/Start, and the opaque dark background sits underneath. A forced network-failure test did not run. Phone rendering, physical touch and OS reduced-motion checks remain unverified because the browser has no resize API and custom test-frame navigation was previously blocked. No retry or alternate route was used for that block. OpenSpec CLI is unavailable; structure and scenarios were checked manually.
