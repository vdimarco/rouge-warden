# Design

Reuse the existing ?debug overlay and G.test interface. Collect at most 600 real gameplay frame intervals and 120 input-to-render-submission timings. Measure browser event timestamp through the next completed render call, including dispatch wait; this is a CPU-side proxy, not GPU completion or input-to-photon latency. Reset frame continuity when hidden, paused, held or outside play. Include long stalls instead of dropping intervals above one second. Calculate FPS from elapsed time, not the average of instantaneous reciprocal frame times. Sort copies only when a report is requested.

Scope: main loop/debug readout, a small pure metrics module and assertion tests, browser diagnostics check and CI, performance evidence protocol and round logs. No rendering technique or asset changes, no telemetry upload. Keep rubric v1's dimensions and historical totals; the Full Swing addendum governs evidence and merge decisions, not a new score scale. Hardware acceptance remains unverified until captured in the user's Chrome workload.

Review follow-up: require the shared input visibility flag when collecting frames or keyboard/pointer samples, and break continuity on every XR visibility event. A blurred headset can keep rendering while simulation is frozen without changing document.hidden. The browser regression forces the shared input flag false and waits for three actual loop ticks before checking exclusion; a fixed wall-clock sleep gave a false pass under slow software rendering. This is a controlled visibility-flag check, not a hardware headset test.
