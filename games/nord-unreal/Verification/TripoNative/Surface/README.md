# Separate Tripo body surface preparation

The [derived body](../../../Data/GraphicNovel/Pilot/CurlyMetalhead/tripo-v3-rig-20261017/derived/native-ready/body.fbx) restores original GLB corner-normal directions and PBR source images while retaining the actual provider rig, normalized size, geometry, UVs and skin weights. The paid provider FBX and all original files remain unchanged. No provider job, render, Unreal process or service was used here.

[Surface.json](Surface.json) records an actual export and fresh-scene FBX import: all 103,544 UV triangles correspond uniquely at 1e-6 UV quantization; geometry differs from the provider by at most 0.133 micrometres; per-corresponding-corner weights are identical; all 61 bones and parents remain, with maximum reference-matrix element error 3.994e-6. Height remains 0.999999527m. Use the same **1.82 import scale for this body and its own clips**; no scale is baked into this derivative.

The exported armature object is explicitly **Armature**, matching the existing relaxed idle/jump. The first surface export inherited the collision suffix `Armature.001` because source and provider were present together. That candidate is rejected for Unreal compatibility and retained under ignored `Saved/Tests/TripoSurface-20261017/rejected-root-name`; [RejectedRootInventory.json](RejectedRootInventory.json) records it. The corrected recipe renames only the disposable source object before importing the provider and asserts the actual fresh-export name. No bone name, hierarchy or bind changed.

The raw provider normals differed from the original by 21.033 degrees mean and 99.34 degrees p99. After this restoration and fresh FBX import, mean error is 0.00222 degrees, p99 0.01688 and maximum 0.660895. Twelve of 310,632 corners exceed 0.1 degrees. This is a measured restoration within explicit precision bounds, not an exact-normal claim. [PrecisionNotes.md](PrecisionNotes.md) records the rejected initial maximum-only gate and the remaining fan-space discrepancies.

The exact original GLB base-color JPEG and packed metallic/roughness JPEG are retained beside the derivative. The identical original standalone normal PNG is reused to avoid another 6.65MB copy. [MaterialVerification.json](MaterialVerification.json) independently imports the FBX and verifies distinct correct base-color and Normal Map image connections and unchanged payload hashes. The FBX material format does not preserve the packed MR graph: native material authoring must bind **G to Roughness and B to Metallic**, with MR/normal as linear data and base color as sRGB. The normal map retains its original GLB convention; native normal convention/tangent import must be explicit.

The CPU author is [prepare_tripo_surface.py](../../../Scripts/prepare_tripo_surface.py). It pins inputs, requires fresh body output files/report directory and checks the actual exported file; run Blender background with `-t 4 --python-exit-code 1`, passing `-- --output NEW_DIRECTORY --report NEW_DIRECTORY`. Other clip files may already occupy the shared output directory; none are overwritten. This checkpoint's exact executed log and recipe hash are retained. `verify_material.py` is the separate executed material check. No Blender render is needed for these numeric/source checks.

Native materials, shading, motion, contacts, props and player-facing art acceptance remain separate work. These assets do not replace the production crew automatically.
