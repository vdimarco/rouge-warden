# NORD browser player

This is the static browser side of the existing UE5.8 game, using Epic's [Pixel Streaming frontend](https://github.com/EpicGamesExt/PixelStreamingInfrastructure/tree/UE5.8/Frontend). It receives actual game video/audio and forwards desktop and mobile touch input. Vercel serves these files; the game and signalling server run separately on the host GPU PC.

[Open the deployed NORD player](https://nord-montreal.vercel.app/). The two temporary PC streams remain dependent on this PC and its GPU headroom; the page stays online if the PC stops. This demo has two independent player slots, one browser per slot. Earlier seven-check public-player runs used a scoped DNS override, which hid a real host-PC Chrome failure: at 00:50 UTC on October 11, ordinary Chrome blocked the original Tailscale Funnel address with `ERR_BLOCKED_BY_LOCAL_NETWORK_ACCESS_CHECKS`. The replacement Cloudflare Quick Tunnel passed seven local checks at 00:56 UTC, seven ordinary Chrome checks on its public preview at 00:57:59–00:58:19 UTC, and seven on the production alias at 00:58:47–00:59:09 UTC **without a DNS override**. A bounded 30-second earlier sample averaged 23.1/24.2 decoded FPS. Real browser controls completed Mission 1 and its save loaded on both peers after an isolated package restart. Full Mission 2, sustained/remote responsiveness, off-LAN access, audible sound and handling enjoyment remain open. See the [connection record](../Verification/BrowserConnection.md), [streaming record](../Verification/BrowserStreaming.md), [GPU recovery and checkpoint record](../Verification/BrowserGpuRecovery.md) and [temporary PC hosting](./HOSTING.md).

Run the following commands from `games/nord-unreal/Browser`:

```bash
npm ci
npm test
NORD_SIGNALLING_URL=wss://your-signalling-host.example npm run build
python3 -m http.server 8081 --bind 127.0.0.1 --directory dist
```

The build reads `NORD_SIGNALLING_URL`, optional `NORD_DEFAULT_STREAMER_ID` (default `NordHost`) and optional `NORD_PORTRAIT_STREAM`. Phones ask the game for frames shaped like the play area in either orientation; this needs the game build with the tall HUD. For an older build, `NORD_PORTRAIT_STREAM=0` keeps adaptive 16:9 phone frames. Desktop remains 1280×720. These are public settings embedded in JavaScript, never secrets. `.env.example` documents them; the build does not automatically load `.env` files. For the local lifecycle helper, use `ws://127.0.0.1:9010` when the player page is also on loopback. A Vercel build and every non-local browser require `wss://`. Credentials, URL query parameters and fragments in the endpoint are rejected. Player-page query parameters cannot override the endpoint or Pixel Streaming settings.

The `nord-montreal` Vercel project is connected to this repository with Root Directory `games/nord-unreal/Browser` and builds `dist` with `vercel.json`. Production deployment `dpl_FYQAQ4mbiKNSKeQyMQ77hLTZPgyB` serves merged commit `d45e2e47` with `NORD_SIGNALLING_URL=wss://officials-soundtrack-engines-institute.trycloudflare.com` and `NORD_PORTRAIT_STREAM=1`; both public settings are configured for production and preview. Upright phones request tall frames, verified against the current game package. Drag-anywhere and opt-in gyro controls are retained; the landscape action row sits clear of the objective. See [delivery and performance evidence](../Verification/BrowserOptimization.md).

Each relevant Git push builds a preview. Preview builds inject Vercel's feedback toolbar, so production receives its own build of the tested commit. Compare all twelve served files with a local build before assigning the production domain. The project skips Git builds that do not touch this browser directory; an environment change alone needs a redeploy. Quick Tunnel hostnames change when the process is recreated, including after a host reboot, so update `NORD_SIGNALLING_URL` and redeploy to restore public play. Keep graphics and frame-size settings unchanged unless a separate quality tradeoff is authorized.

Deploy through the connected Git source. Never run a Vercel upload from the live service checkout: its ignored `Saved/BrowserStreaming/relay/` and `Builds/` directories contain private relay settings and saves, and Vercel does not use `.gitignore` as an upload boundary. If a CLI upload is needed, use a separate clean export containing only the intended browser source or static output. An empty endpoint builds an explicitly offline page; it does not start the game.

Connect, choose a free player, then click **Play with sound**. Click the video to capture mouse/keyboard; **Esc** releases it. `NordHost` is Player 1 and `NordFriend1` is Player 2. They are separate Unreal processes connected to the same multiplayer session. The temporary signalling server accepts one browser per stream and refuses an additional subscriber to an occupied slot. The player lists streams reported by the server; sharing one stream would not create an independent character.

WSS signalling alone does not establish a WebRTC media path. The host now has an optional, co-located TURN/TLS relay for the two browser streams; an isolated forced-relay test received real 1280×720 VP8 video and a live data channel. After enabling it, seven ordinary public-player checks and seven forced-relay checks passed; Android Chromium emulation also received actual video through the relay. The user has since confirmed phone video loads and looks good. The earlier browser checks used STUN-only ICE and remain historical. The PC must remain powered on, connected, and running the game, signalling and relay services. See [temporary hosting](./HOSTING.md) and the [mobile connection record](../Verification/BrowserMobileConnection.md).

The player uses the existing native controls and campaign. Touch-capable devices show a left movement stick, round Sprint, Jump, Use/car and Menu buttons with action icons, tactile pressed states and 12 px gaps in two bottom-right rows (72–88 px square targets, 88 px on a full-height portrait phone). Entering a car automatically replaces the movement stick with Left/Right steering and changes the right actions to Gas, Brake/Reverse, Exit and Menu. Hold Gas with one thumb and steer with the other; Brake overrides Gas, stops forward motion, then reverses. Exiting restores walking controls. Drag anywhere in the game area to look, including the space around a letterboxed picture. For motion control, open ☰ Menu, tap Gyro look, allow motion access if asked, then move the phone left/right or tilt up/down. Tap Gyro look again to turn it off; dragging works alongside it. Missing or denied sensors leave a message in the menu. Crew, Recover, Race and Comic buttons use the existing C/R/T/F2 bindings. Tap Use to acquire or release the worklight, then aim by dragging or with gyro. Several fingers can move, look and act together; lift/cancel, rotation, focus loss and disconnect release touch-held keys. Landscape gives the widest game view. On a touch screen the game goes fullscreen on the tap that starts it (Play as or Play with sound); Start keeps the page in its window, so ☰ Menu stays in reach over the start screen. Fullscreen in the menu leaves and re-enters it in any state. The full trailer fills the screen, and goes fullscreen where the browser allows it. Mobile landscape fullscreen displays the entire frame to all four edges, with the action grid clear of the mission card and speed digits; the touch buttons replace the lower keyboard hints. Native phone frames match the play-area aspect ratio in portrait, landscape and fullscreen. CSS preserves the whole picture without stretching; a previous frame may briefly letterbox during rotation. Each adaptive level uses the same total pixel budget in either orientation (edge² × 9/16), rounded down to even encoder dimensions. See [fullscreen checks and limits](../Verification/MobileFill.md). Walking and driving cameras keep a character-centered orbit between -25° and -5°, so vertical looking retains the full character. Worklight aim stays independent. Phones start with a 960×540 pixel budget (shaped to the play area) with a 2 Mbps ceiling, rising to a 1280×720 pixel budget/4 Mbps after sustained healthy playback. After a five-second settling period, five consecutive poor receiver samples (or two below 12 FPS) step down to a 960×540 pixel budget at 2 Mbps, then an 800×450 budget at 1.5 Mbps, retaining 640×360/1 Mbps only for continuing severe pressure; fifteen healthy samples restore one clearer profile at a time. A single freeze does not permanently lower quality. Swipe sensitivity stays consistent across stream sizes. Desktop keeps 1280×720. Double-tap Move and keep the second touch held to sprint, or double-tap Sprint while moving; releasing Move clears the sprint latch. Dragging a held action button also turns the view, while steering buttons keep steering. In a pond, Jump becomes Stroke; move toward a bank to return to walking. Eight of the sixteen ambient cars circulate in the starting neighbourhood, with the others travelling district routes. The smaller circular minimap shows a 500-metre diameter with mission/home direction markers and the nearest parked cars. No account/session allocator, microphone or headset input is added.

The title loop now releases its media source during connection, intro, play and backgrounding. Data saver/reduced motion keep the poster without downloading the loop; the full trailer loads only on an explicit Watch tap and releases its source on close. Rotating during play cannot reload hidden trailers.

The [QA plan](../Verification/QAPlan.md) says which of the checks below to run for a change, a deploy or a host restart.

`npm test` checks endpoint validation and touch movement/action ownership, deadzones, normalization, cancellation, lifecycle release and keyboard/assistive button activation. `npm run test:browser` reuses the repository's installed `qa/browser` Playwright and system Chromium to check offline/error states, click-to-connect, ignored URL overrides, and 720p/1080p/narrow-page layout without a running game. Set `NORD_PLAYWRIGHT_PATH` or `NORD_CHROMIUM_PATH` when those existing tools live elsewhere. This test temporarily rebuilds `dist` and restores its original endpoint in `finally`; do not run it during a deploy. These checks pass; real-media evidence and outstanding manual/network checks are recorded separately in [BrowserStreaming.md](../Verification/BrowserStreaming.md).

`npm run test:media` checks advancing real phone-shaped video and orientation changes while both page videos stay unloaded, recording MP4 requests without downloading them. Use the same `NORD_PLAYER_URL` and `NORD_PLAYWRIGHT_PATH` settings as the live tests; it requires a free default player slot and never restarts the host.

Control-channel failures release input and close the failed session so Reconnect opens a fresh stream. Late video readiness/playback events cannot hide a failed or disconnected state; occupied-slot refusal still lets you select another player. Player selection waits for the current subscription outcome so an older refusal cannot hide the new stream. The held movement stick stays visible at 70% opacity to show direction. The real-stream suite includes injected control-channel failure and recovery against the actual game.

For an upright real-stream measurement, add `--portrait` to `stream-sample.mjs`; the default remains sideways. Both modes record native dimensions, decoded FPS, drops, freezes and buffer delay without changing the character position.
