# Montréal retained east context extension

Native authoring and fresh-load verification passed on 2026-10-14, including the canonical Plateau preservation/collision checks. Physical crossing and running-jump containment are still being tested; this is not final rendered/package acceptance. The extension opens only the retained 200 m context east of the original rectangle: x=55,373.303–75,373.303 cm, y=−46,754.4–69,018.4 cm. Existing context road/apron visuals and mapped building-shell collision are reused. No streets, buildings, traffic, missions, residents or spawn positions are invented or regenerated.

The retained OpenStreetMap snapshot and context manifest supply 143 road segments across 37 ways. Every added segment matches an already-rendered context segment. The former Rue Panet and Rue de la Visitation exits connect into the extension road network. Twelve mapped outer crossings form ten distinct roadway corridors; three overlapping north crossings are grouped into one illustrative closure. Orange barricades and RUE BARRÉE placards are fictional game furniture, not surveyed municipal construction. All new decoration is nonblocking. Its forty small batches contain 14,160 triangles; source polygons and signs remain inside the extension strip.

Source: `Data/LaFontaine/osm.xml`, © OpenStreetMap contributors, [ODbL 1.0](https://www.openstreetmap.org/copyright). `extension.json` pins SHA256 for that snapshot, original layout/header, context manifest and old closure manifest, and records every source way/node pair. Heights and flat context surfaces retain the existing background layer's estimates and limitations.

Four new hidden engine-cube actors provide collision: a floor with top Z=0, overlapping the unchanged original floor by 50 cm, and 400 cm north/south boundary strips overlapping the unchanged original walls by 35 cm. Exactly one original actor changes location: the existing east `District edge` moves +20,000 cm X. All four original duplicate-labelled boundary actors remain. A separate full-length east cap spans Z=200–400 cm above the retained 200 cm original wall. The existing eight closure meshes and two signs remain as actors and assets, hidden and invisible with collision/material/transform/shadow properties preserved. The old floor, other walls, park, gameplay actors and environment stay fixed.

The old east wall retains its original 200 cm height. Native running-jump QA proved a real escape over that height; the new upper cap and taller extension strips address it. Fresh-load readback and the same native running-jump containment suite now pass. The suite retains 110 residents, 16 traffic cars, strict capsule containment and actual airborne contact; all 19 behavior checks pass. Package and rendered acceptance remain separate. Flat visual roads/aprons are not newly modelled curbs, elevations or detailed façades. Traffic remains on the original graph. The separate `Source/Quebec/LaFontaineExtensionMap.h` supplies expanded bounds and extension-only `RoadSegments`/`RoadSegmentWidths` (143 entries). Its new `RadarRoadSegments` array contains all 663 original initializer rows byte-for-byte and coordinate-for-coordinate, then exactly those 143 extension rows: 806 total. A comma on its own line separates the unchanged original last row from the suffix. Metadata pins the original prefix SHA256 and generator SHA256. The runtime selects this combined array only for actual LaFontaine/PIE radar; traffic, Toronto and unknown synthetic-world callers retain their existing arrays. The original LaFontaine data/header remain byte-identical.

From games/nord-unreal:

```text
python3 Scripts/montreal_east_extension.py
python3 Scripts/test_montreal_east_extension.py
```

Generation writes only this folder and the new header. `Geometry/` is ignored and must be regenerated before native import. The CPU test rebuilds into a temporary directory, verifies source hashes, road joins, floor/wall joins, closure containment, noncollapsed OBJ/float32 triangles, deterministic metadata/header and pre-mutation rejection of rendered/dirty/stale/duplicate/missing-source conditions. It also rejects undeclared changes to original actor semantics. It does not emulate Unreal asset import or persistence.

`preflight` validates every source/OBJ/hash/header, exact original floor/four-wall transforms, all 742 context actors, ten old nonblocking closure actors, existing materials/Nanite usage, fresh destination and fresh backup path before package/map mutation. It copies the map package and sidecars, hashes every original Content file and saves original actor semantics. It never changes an existing material or destroys an old actor. Imported meshes go only under `/Game/Plateau/EastExtension`; only the existing LaFontaine map package may change. Existing extension assets or actors cause rejection; failed attempts must be preserved and restored by root before retrying.

Fresh-load readback uses the same script with `-NordMontrealEastVerify` and the same backup argument, or calls `verify(unreal, project_root, backup_path)`. It checks original captured actor/component semantics with exactly the declared location/visibility allowances, all protected Content hashes, 54 added actors, saved source geometry, material references, Nanite settings, collision and hidden flags. Snapshots cover actor identity/class/label/transforms/folder/hidden/collision/tick; component identity/transforms/visibility/tick/active/material/mesh/collision/shadow and instanced transforms; resident route/style/phase and car paint. They are explicit semantic snapshots, not a claim that every internal transient engine field is serialized.

Existing `plateau_edges.verify` expects the old decorations visible. The canonical verifier branches its caller when `Plateau east extension collision floor` exists and invoke the new verifier using the preserved backup path. The radar is wired without expanding traffic. Root must separately prove old-edge crossing by foot/car, outer containment including jumps, ground/building collision, mission-route preservation, current native views and package dependencies. No original C++, verifier, package, engine, GPU or service was touched by CPU authoring.
